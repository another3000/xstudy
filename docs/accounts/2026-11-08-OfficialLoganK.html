5. 增长机制拆解

  1. 互关 / 粉关比： ≈112.9:1——健康。关注 3418 对 DevRel 偏高，学内容不学把关注加到三千。
  2. 回复工时： 中低。发版线程里补充链接和案例，很少去别人帖下养号。
  3. 钩子话术： Introducing + 能力子弹、公开价、内测人数、「25 trillion tokens」、偶尔一个词吊胃口、人生金句。
  4. 书签型 vs 虚荣赞： 评测建议和对谈录像书签密；一字「Gemini」和用量狂欢帖赞多、存得少。XLeadForge 样本里超过 280 字、三行以上的帖书签率明显高于 80 字以内短句——他的发版长帖符合这条，单字钩正好落在反面。
  5. 权威资产： Gemini API 发版权、AI Studio、Kaggle、能拉来 Brin / 产品负责人对谈、Fairwind 安全项目。数字是内部可核对口径（10 万人战测、72 小时 25T token、$2/$10）。
  6. 跨平台： 指向 API 文档、YouTube、AI Studio、线下 Bench Summit（旧金山）。
  7. 漏斗： 金句/悬念进场 → Introducing 清单或评测建议被收藏 → 开发者打开 API / AI Studio / 峰会报名。信任来自「我是发版的人」而不是互关。

7. 可学习清单（→ 微李玩AI / LIS / AI入企 / 小程序）

  1. Introducing 四件套（名字、谁先用、能力子弹、价格或通道） → 微李玩AI / 小程序：发版不要只写「上线了」，写清内测范围、三条能力和在哪体验。
  2. 公开战测人数 → AI入企：用「在 N 个科室/N 位检验师跑了 M 周」代替「我们很重视质量」。
  3. 用量 Number Drop → LIS：72 小时 25T token 是实验室规模；可迁成「上线 72 小时处理了多少份报告/多少条医嘱」，让院方看见负载而不是形容词。
  4. >25% 时间做评测 → 输血信息化 / AI入企：落地项目应先做一套医院在乎的评测（交叉配血规则、危急值、漏检率），再要求模型实验室或供应商对这套题负责。
  5. 发版后续楼补通道 → 小程序：主帖讲能力，第一条回复放操作路径或回放，避免主帖堆链接。

8. 风险与不该学

  • 一字悬念只适合真有权杖、几小时内能兑现的人；医疗账号发「LIS」一个词再消失，是消费信任。
  • 人生金句能爆，但品牌会变成鸡汤号。微李玩AI 可以偶尔用，不能连续发。
  • 关注三千加：粉关比尚可，不代表我们要学广撒关注。
  • 发版脉冲依赖公司日历，个人号照搬会变成「没发布就停更」。

9. 对我们的行动建议

  1. 下次产品或内容更新，按 名字 + 谁先用 + 三条能力 + 在哪体验 写一条 Introducing，不要只发截图。
  2. 选一条院内或客户项目，公开一个 72 小时用量或战测人数（人审后发）。
  3. 为人审加一条红线：禁止单独发没有下文的单字/单句悬念。
