7. 可学习清单（→ 微李玩AI / LIS / AI入企 / 小程序）

  1. 「这次改动如何完全可验证？」 → LIS / 输血信息化：把这句话设成人审前的固定提示，要求 Agent 对照危急值规则、配血步骤或界面点选把结果跑出来，而不是只改代码。
  2. 先刹车再加速 → AI入企：对外讲 Agent 不要从「更快」开始，从自动评审、领域词表、可回滚（他另有一条 expand/contract PR 提示词）开始，否则医院只会看到 slop。
  3. 可读性改写成可验证 → 小程序 / 定制开发：评估模块时少问「好不好读」，多问「能不能独立测、能不能让 Agent 自己验证」。
  4. 外部验证当社会证明 → 微李玩AI：与其自夸方法好，不如展示第三方引用、雷达、客户复现。一篇评估论文顶过十次自我表扬。
  5. Prompt of the day 系列化 → 微李玩AI：每周固定一条可复制指令，比每天一条宏观判断更保值，也更方便导向课程或清单。

8. 风险与不该学

  • 半认真禁令（禁用 useState）有传播力，迁到医疗会显得轻佻，只能学「把 Agent 推进成功坑」的结构，不能学抬杠题材。
  • AMA 和「给我 aha」只在你真的在发布、真的想听现场时有效；无产品时会变成回复诱饵。
  • 课程预热可以学「刹车叙事」，不要学尚未兑现的「职业生涯最大」话术——那是他的历史销量在托底。
  • 日更多条适合全职教师，我们若模仿频率会稀释判断密度。

9. 对我们的行动建议

  1. 本周置顶或固定一条 可验证提示词：「How do we make this change fully verifiable?」的中文版，用在 LIS/小程序的一次真实改动上，并公开验证过程。
  2. 发 1 条 刹车清单：自动评审、领域词、可回滚，三件套对医院讲比「我们上了 Agent」有用。
  3. 人审红线：可以提问，但主帖必须附带一句可复制动作；禁止纯抬杠禁令和空 AMA。
