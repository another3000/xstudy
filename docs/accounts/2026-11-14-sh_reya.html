7. 可学习清单（→ 微李玩AI / LIS / AI入企 / 小程序）

  1. 给 Agent 和仪表盘的标题制定同一句式 → LIS / 输血：待办和危急值列表不要混用名词、动名词和祈使句。同一主语就省略主语，动词时态保持一致。
  2. 重要的差异放在前两个词 → 对照亚马逊邮件把状态放开头。报告列表应是「危急：钾离子…」而不是「您的一份检验结果已经…」。
  3. AI 摘要必须同一结构、同一词 → 不要这一行叫「问题」、下一行叫「页面」。质控主题卡用同一模板，变化只表达真的差异。
  4. 抽取任务写清基线，不只报倍数 → 对照 Quail：朴素基线 vs 调优基线，平均与最高分列。院内抽取（例如研究场景里的剂量、字段）先报样本和对照，再报快了多少。推文可以简化，文档不行。
  5. 个人/团队 OS 按工作量分流 → 对照她的 stack：大改走更重的 Agent，小改走轻模型，人负责提需求和删代码。AI入企先写清「人闸门在哪一步」。

8. 风险与不该学

  • 推文「2x faster and cheaper」与正文 4.7x / 1.8x 两条基线并不等同。对外传播可以简化，案例和标书必须用正文口径。
  • 临床笔记、药物剂量只是论文式示例，不能写成已验证的临床功能。
  • 金句和「不要从 slop 里挖钻石」可以当结尾，不能当正文。
  • 与 Hamel 的书是正资产，但不要把签售和订单链接当成日常增长模板。

9. 对我们的行动建议

  1. 本周把一条 LIS/小程序里的 AI 列表标题 按五原则改写：同一句式、差异词前置，并发 before/after。
  2. 若有字段抽取试点，补一页 对照基线（朴素提示词 vs 现行方法，样本数、耗时或费用），禁止只写「快了两倍」。
  3. 人审红线：不把研究示例写成临床结论；对外数字以可引用的正文为准，不以推文钩子为准。
