7. 可学习清单（3–5）

  1. 结论必须带边界 → 微李玩AI：不要只说「这个模型更适合写代码」。补上跑了多久、在哪类任务上没触发拒绝、和哪一个对照比。
  2. 观点篇和证据篇拆开，证据篇才是资产 → LIS / AI 入企：先发一句现场判断，第二天补「时长、环境、对照、失败」。让收藏发生在第二篇。
  3. 用旧工艺类比新方法 → 院内培训：把「看模型思维链再改」说成大家熟悉的「看日志、下断点、补一刀」，比堆缩写更容易被记住。
  4. 转写对谈要分块，不要感想 → 会议或厂商交流后，按「范式 / 适用边界 / 选题 / 预测」四段写一页，给没参加的人收藏。
  5. 声援和情绪不当主粮 → 回看时用 BIR，而不是用曝光，决定下一条还要不要站队。

8. 风险与不该学

  • 限流 / 审核风险：低。技术细节密集，对非同行不友好，但不涉及违规内容。
  • 信任与品牌损耗：把未完成的实验写得像生产建议，会被现实打脸。他常用 "first impression"、"may accelerate"，学这个限定词。
  • 与我们定位冲突点：微李玩AI 不必追 kernel hillclimb 和内部模型代号；要学的是笔记结构。院内内容更不宜卷入厂商人事站队。

9. 对我们的行动建议

  1. 本周把一次真实试用写成两条：第一条只给判断和对照；第二天补环境、时长、失败边界（人审后发）。
  2. 选一个抽象概念（比如「验证闭环」），用一个旧工艺类比写清楚，不堆英文缩写。
  3. 若要引用一场会议或播客，按四块转写，不要只发「强烈推荐」。
